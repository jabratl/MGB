0.0.96 (S3) per-extension storage + runtime id
- ChromeBridge.kt: chrome.storage local/sync/session per extension (filesDir/exts_data/<id>/local.json, sync.json; session in memory); quota 10 MB local / 100 KB sync for extensions
- Bridge messages carry the extension id; token is per extension (ContentInjector.tokenFor), so an extension cannot speak as another or read its data
- Events, answers and runtime.onMessage replies are addressed to one extension (several extensions can share one page frame)
- Installed extensions are limited to storage.* + runtime.sendMessage for now (runtime.sendMessage -> "Receiving end does not exist" until S4/S5)
- chrome-shim.js: sends x=id, ignores events/answers meant for another extension
- ExtListScreen.kt: Remove also wipes the extension's storage
- V77 (built-in) behaviour unchanged: same files, same token, same handlers
0.0.95 (S2) content scripts of N extensions
- ContentInjector.kt: every enabled extension in files/exts/<id>/ gets its manifest content_scripts injected (js, css, run_at, all_frames, world MAIN)
- Full match / exclude_matches check at runtime (path too, not only origin); css injected as <style>
- Per-extension cache (re-read when manifest/version changes); broken extension is skipped, others + V77 unaffected
- Toggle/remove/update applies to tabs opened afterwards (open tabs keep old scripts until closed)
0.0.94 (S1) Settings > Extensions
- NEW ExtListScreen.kt: Add (file picker .zip/.crx), list, on/off switch, remove (confirm), tap = details
- Permission summary dialog before install (sites, page scripts, permissions in plain words); Cancel = discard; same id = Update
- SettingsScreen.kt: new category "Extensions" (row shows "N on / M")
- BrowserExtras.kt: new pickExtension() launcher (registered last, old launcher keys unchanged)
- Installed extensions still do nothing (S2+ runs them)
0.0.93 (S0) multi-extension foundation
- NEW ExtRegistry.kt: install (.zip / .crx) into files/exts/<id>/, manifest parse, id, enable flag, remove
- .crx header cut (CRX2 + CRX3); Chrome id from crx header, else manifest "key", else hash of name
- two-phase install: prepare (unpack to hidden .stage_*, read manifest) -> commit / discard (for S1 permission dialog)
- ExtUpdater.kt: safeFile + unzip made internal (reused, logic unchanged)
- No UI yet, nothing calls ExtRegistry yet (S1 does), so app behaviour is unchanged
