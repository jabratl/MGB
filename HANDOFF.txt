0. THE ONE HARD FACT THAT SHAPES THE WHOLE DESIGN (read first)
====================================================================================================
Android deletes app-private storage (filesDir, SharedPreferences, Android Keystore keys) on uninstall and the app
gets NO callback / cannot show a dialog at uninstall time. So:
 (a) The vault container must live in a USER-PICKED shared folder (SAF tree uri, ACTION_OPEN_DOCUMENT_TREE). That
     folder survives uninstall. Always write-through there; never keep the only copy in filesDir.
 (b) The container key cannot depend on the Keystore alone (Keystore key dies with the app). Use envelope encryption:
     random DEK (256-bit) wrapped by a KEK derived from the user's vault passphrase (PBKDF2-HMAC-SHA256), plus a second
     wrap by a one-time RECOVERY KEY. Keystore/biometric only as a per-install quick-unlock wrap of the same DEK.
     After reinstall: user picks the folder again + enters passphrase (or recovery key). Documented in UI.
 (c) "Choose what to delete permanently / what to keep on device" cannot run at uninstall. It runs BEFORE uninstall in an
     "Exit / Uninstall prep" wizard (V9). Per category 3 choices: KEEP encrypted in vault folder | EXPORT readable copy to a
     plain folder | DELETE permanently (wipe). If the user just uninstalls without the wizard, nothing is lost: the encrypted
     container is already outside the app and stays (default = keep).
 (d) Existing object Vault (Vault.kt) is a small Keystore AES helper used by PasswordStore + EmailAlias (encrypt/decrypt/unlock).
     DO NOT rename or change it. New code uses new names: VaultCrypto, VaultStore, VaultScreen, VaultItems, VaultFiles, VaultExit...
 (e) minSdk 24: SAF tree works on all supported versions. Android 11+ blocks picking the root of Downloads/Documents; the picker
     UI must tell the user to create/choose a sub folder (e.g. "ThazirVault"). Do not use MediaStore for the container
     (ownership is lost after reinstall).

KEY DATA SHAPES (design contract - V1/V2 must implement exactly; later steps only consume)
- Container folder (SAF tree, user chosen, e.g. ThazirVault/):
    vault.hdr   JSON {v:1, kdf:"PBKDF2WithHmacSHA256", iter:N(>=310000), salt:b64, wrapPass:b64(iv+gcm(DEK)), wrapRec:b64, recSalt:b64, check:b64, created:ms}
    index.enc   AES-GCM(DEK) of JSON {v:1, items:[...], folders:[...]}  (written as index.tmp then swapped; keep index.bak = previous)
    d/<16hex>.bin  chunked AES-GCM stream: header(magic "THV1", chunk=64KiB, nonce prefix 8B) then per-chunk (ctr in nonce) so random access / streaming works
- Item (VaultItems): {id:16hex, type:"bm"|"hist"|"page"|"file", title, url, time, folder, size, mime, orig:{name,rel,uri?}, blob:"d/<id>.bin"|null, flags}
  bm/hist keep data inside index (no blob). page/file have a blob. Filenames on disk are random ids; titles live only inside encrypted index.
- State machine VaultStore.state: NONE (no vault) | FOLDER_MISSING (permission/folder gone - NEVER auto-create a new empty vault) | LOCKED | UNLOCKED.
- Prefs "mgb_vault": tree uri string, quick-unlock wrap (Keystore, per install), autolock idx, hide-recents flag, fail count/lockout time, last index version.
- Update safety: header v and index v fields + migrate() in VaultStore; never drop unknown JSON fields (copy-through) so a newer file opened by older app is not corrupted.
