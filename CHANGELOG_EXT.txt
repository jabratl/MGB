0.0.101 (S8) extension safety
- NEW ExtSafety.kt: manifest v2 and nativeMessaging extensions are refused when added (message shows the reason, nothing is installed); an older install of such an extension is turned off at app start and cannot be turned on
- Extension pages opened in a tab only use the CORS-free proxy (and their header rules) for sites in their host permissions, like extension windows already did
- Crash isolation: if the render process of an installed extension window dies, only that window closes (before: the app could be killed); background workers were already isolated in S5
- Add dialog says which permissions are accepted but do nothing in MGB yet (webRequest, downloads, ...)
- Diagnose: new rules 88-92 (worker parked, worker did not start, extension window crashed, worker errors, extension refused / turned off)
- ExtSafety.kt, ExtListScreen.kt, ExtScreen.kt, TabManager.kt, ExtBackground.kt, ContentInjector.kt, DiagRules.kt, DiagReport.kt
0.0.100 (S7) declarativeNetRequest for installed extensions
- Header rules (modifyHeaders) per extension: updateSessionRules / updateDynamicRules / getSessionRules / getDynamicRules, own list and own saved dynamic rules for every extension (the built-in extension is unchanged)
- Static rulesets from manifest declarative_net_request.rule_resources, getEnabledRulesets / updateEnabledRulesets
- Rules change only the requests that extension makes itself (worker, popup, options, its pages in a tab), only for sites in its host permissions, only while it is on; removing an extension deletes its rules
- Needs permission declarativeNetRequest (or declarativeNetRequestWithHostAccess). Block / redirect rules are accepted but do nothing yet; webRequest and downloads are still not available for installed extensions
- HeaderModes.kt, EngineHost.kt (proxyFor takes the extension id), ExtApi.kt, ExtBackground.kt, ExtScreen.kt, TabManager.kt, chrome-shim.js
0.0.99 (S6) per-extension chrome.* api
- NEW ExtApi.kt: gate = every call of an installed extension is checked against its manifest permission (storage, alarms, notifications, contextMenus, scripting, cookies) and api list; V77 rule unchanged
- popups / options pages of an installed extension can now use chrome.tabs (query, get, create, update, remove, reload, sendMessage, getCurrent), chrome.windows, chrome.action (ignored), chrome.permissions (read-only), chrome.scripting.executeScript / insertCSS, chrome.cookies
- tab url / title / favIconUrl are removed for an extension without the "tabs" permission or a host permission for that tab (results and tabs.onCreated / onUpdated)
- scripting.executeScript / insertCSS: needs host permission (or activeTab = tab on screen); files come from the extension's own folder
- relative urls in tabs.create / tabs.update / windows.create resolve inside the extension; sender of a message carries the extension id and the worker / popup url
- alarms per extension (saved, min period 30 s, wake the worker); notifications (system notification, toast when notification permission is off, no click event); contextMenus (stored only, no menu shown yet)
- ChromeBridge.kt: "ext.<api>" handlers are preferred for installed extensions; TabsApi.kt: tab events also go to installed extensions; chrome-shim.js: scripting.insertCSS
- Not for installed extensions yet (answer "Not supported in MGB"): downloads, declarativeNetRequest, webRequest, offscreen, sidePanel, runtime.getContexts (S7 / S8)
0.0.98 (S5) background service worker per extension
- NEW ExtBackground.kt: manifest background.service_worker (classic or type=module) runs in its own hidden WebView, started lazily, stopped after 45 s without activity (bridge call, network request, pending reply)
- importScripts works (sync XHR + eval); self.skipWaiting / clients / registration stubs; install + activate events fired after load
- Wake: runtime.sendMessage from content script / popup, alarms, tabs events the worker listened to last run, runtime.onStartup (app start); runtime.onInstalled on install / update (ExtApi.sync from Settings > Extensions)
- Crash isolation: at most 3 workers at once (least recently used stops), 20 s load timeout, 3 render crashes in 5 min park that worker only; other extensions and V77 unaffected
- The worker can read only its own files; network (CORS-free proxy) only for its host permissions
- EngineHost.kt: serves the generated ext/<id>/_mgb_bg.html, status shows "Extension workers"; ExtListScreen.kt: toggle / remove / install / update call ExtApi.sync
