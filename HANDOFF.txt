1. PROJECT SUMMARY
Thazir (internal project MGB) is an Android WebView browser built in Kotlin with native Views and Material 3 DayNight NoActionBar. It includes a native speed-dial HomeView, multi-tab manager and switcher, bookmarks/history, privacy/ad blocking, native download and media detection flows, built-in Media3 player, extension compatibility/runtime bridge, userscripts, saved pages, translation hooks, password/site permissions, appearance customization, backup and diagnostics.

4. DESIGN RULES — BASELINE AUDIT
Native app:
- Framework: Theme.Material3.DayNight.NoActionBar; native Android Views built mostly programmatically. Existing layout XML is limited and should stay limited. No Jetpack Compose migration in this plan.
- Font: system sans-serif. Titles/labels commonly use Typeface.create("sans-serif-medium", ...); no bundled custom font resources found. Keep this to avoid added assets and font licensing/weight problems.
- Light palette (values/colors.xml): mg_bg #FFFFFF; mg_surface #F5F5F7; mg_surface_variant #ECEDF0; mg_primary #D93A5C (rose); mg_on_primary #FFFFFF; mg_text #14171C; mg_text_dim #5F6673; mg_outline #DCDFE5; mg_error #D93025; mg_success #1E9E5A; mg_toggle_on #5B4BD6; mg_toggle_thumb #FFFFFF.
- Dark palette (values-night/colors.xml): mg_bg #0A0C10; mg_surface #14171C; mg_surface_variant #1F232A; mg_primary #F2708A; mg_on_primary #3A0A15; mg_text #ECEFF4; mg_text_dim #98A0AE; mg_outline #2A2F38; mg_error #FF7B72; mg_success #4CD08A; mg_toggle_on #9A8CFF; mg_toggle_thumb #FFFFFF.
- Theme maps Material 3 primary/surface/on-surface/outline/error and surface-container roles to mg_* tokens; status/navigation bars follow light/dark bool mg_light_bars.
- Brand signals already present: rose primary in native app, violet toggle/selection, icon background #1B1630. Prior A11 appearance work adds small violet dash section markers and restrained haptic/press feedback. Do not abruptly replace every token without checking contrast and existing icon/state semantics.
- Existing screen spacing is mostly 14–20dp horizontal padding; settings headers ~56dp; search fields ~48dp; row minimum heights ~52dp; cards use 12–16dp corner radii; bottom bar 52dp default / 44dp compact; bar outer margins 10dp and vertical margins 6–8dp. Other dialogs/cards use 20–24dp radii. Treat these as observed ranges, not rigid universal constants.
- Touch targets: common controls 40–48dp; prefer >=44dp for primary touch actions. Respect system insets/cutouts and keyboard resize.
- Corners: rounded cards and pills; existing bottom bar drawable is a pill. Keep elevation/shadows subtle; use outline and surface contrast before strong shadow/glow.
- Icons: existing vector drawables in res/drawable, mostly 24dp. Reuse exact icons where semantically appropriate; add vector XML only if missing. Avoid emoji as primary app icons.
- Animation: native View animations/animators already used. Existing Reduce motion setting exists; new motion must respect it. Keep normal transitions short and restrained (~150–250ms as design target, not a current global constant).
- Dark/light: both are first-class and implemented via resource qualifiers + UiMode. Every new native surface must use themed resources/context and be tested in both modes; never hardcode a light-only surface.
- Responsive: native app primarily phone-first; AndroidManifest handles orientation/screenSize/smallestScreenSize/screenLayout/keyboardHidden/uiMode config changes. No meaningful swNNNdp resource breakpoint system was found. Extension web UI has CSS media breakpoints at 360/400/420/520/760px and coarse pointer >=44px; reduce-motion CSS exists in theme.css. Do not assume native UI already has tablet breakpoints.
- Extension web theme CSS (assets/ext/theme.css) uses 4/8/12/16/24px spacing tokens; 10/14/20px radius tokens; compact font scale 11/12/13.5/16/20px; tap token 40px (44px for coarse pointer); dark default palette with light override. CSS uses system font stack unless page-specific serif/monospace preview is intentional.

Target direction for future redesign (design note, not current implementation):
- Hybrid minimal + futuristic; retain Thazir's violet identity as the primary signature accent, with restrained neutral surfaces. Existing rose primary is legacy; S1 must migrate tokens carefully and test all native surfaces. Do not blanket-apply glow/glassmorphism.
- Obsidian/deep neutral dark surfaces, calm off-white light surfaces, violet accent and soft-violet selected states; keep error/success semantic colors independent.
- Prefer consistent 16–20dp cards, 12–16dp controls, clear hierarchy, compact labels, predictable spacing and 44dp+ touch areas.
- Home screen should be calm and customizable, not a dense widget wall. Address bar stays the main navigation affordance. Tabs should prioritize readable previews and quick close/switch. Settings should expose category + search and concise summaries.
- Use actual labels and accessible content descriptions; preserve screen-reader focus order, contrast and text scaling. Avoid decorative animation that blocks navigation.
